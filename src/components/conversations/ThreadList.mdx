# ThreadList

The comments on a project or an issue: Ship's reads, writes and words, drawn
by the kit's **ConversationLayout** in one column beside the page.

**Seen in** — *Pages/In the shell*: **Issue**, **Project** and **Issue
Comments Hidden With New**. Each state of a card, a thread and the box has its
story in the kit (*Conversation/ConversationLayout*).

## When

- Beside an issue's or a project's page, in the column the header's comments
  button shows and hides (ONE-6, step 4c).
- Wherever somebody may write. Leave a write callback out where nobody may,
  which removes the control instead of disabling it; pass `disabledReason` when
  nothing can be written here (an archived file, signed out): each box becomes
  a line saying why, and React, Edit and Delete are not offered.

## When not

- For conversations elsewhere that mention this file → **MentionList**, in the
  **OverviewPanel**. The distinction is the model (CON-9), not a layout choice.
- For a single comment box on its own → **ConversationBox**.

## How

```tsx
import { ThreadList } from '@/components/conversations/ThreadList'

<ThreadList threads={threads} onStart={start} onReply={reply} about={issue.addr} unread={unread}
  onReact={react} onDeleteMessage={remove} onEditMessage={edit} />
```

- The props are production's `ConversationsProps`. A write resolves `false` on
  a refusal, which keeps the box, the edit or the delete question open with
  what was typed.
- `ThreadListView` is the drawing alone, with the reads handed in — for a test
  or a caller that already has them.

## What it owns

- **Reading the references and the reactions once for the whole column**, and
  re-reading reactions after a write rather than patching the count.
- **Ship's words** where the kit's differ: "No conversations yet.", "Reply…",
  "Delete this message?", "Delete message", "Message actions".
- **A thread holding an unread reply opens by itself**, without taking focus.
- **The drafts**, keyed by the object for a new conversation and by the thread
  for a reply.
