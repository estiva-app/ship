# ForeignObject

A file Ship lists by itself — a Folder's own projects and issues, the file a
hand-off page names, a file placed under another — as the kit's **LinkRow** or
**LinkCard**, the same widgets a message draws (Katerina, 30 Oct). What is
Ship's here is only which of the two its manifest hints, and where it opens.

<Canvas of={ForeignObjectStories.Card} />

## When

- A file listed on its own, not linked from text: a row on the Folder page,
  the card on a hand-off page, a file under **Related**.
- Whatever the kind. An app nobody here has heard of still resolves to one of
  the closes this consumer implements, through the fallback chain.

## When not

- A file a message or a description links → **MessageChip**, **MessageRow**,
  **MessageCard**, placed by where the link sits.
- Never branch on which app it came from: not one line here knows what Peek
  is.

## How

```tsx
import { ForeignObject } from '@/components/ui/ForeignObject'

<ForeignObject object={file} conversations={counts[file.ref]} />
```

- `conversations` is the caller's to read and this part's to draw, as the
  kit's count opening the conversation: a Folder listing does not read it, a
  Related section does.

## What it owns

- **Row or card**, by the manifest's widget chain, terminated in `message`,
  `card` or `row`; a message is the kit's row of a person's words.
- **"Not available"**, in the row's or the card's place, for a file this
  reader may not see, with the way to open it in its own app: a gated read and
  an empty file never look alike.
- **Words, not pickers**: a listing is not where a file is changed.
- **Another app's file opens in a new tab**, as a message's links do.
