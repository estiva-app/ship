# PartCard

One block of another file, live inside a message (SPEC §13.6.1): the package's
PartCard frame, with the block Ship reads drawn inside it.

## When

- A `part` a message shows, under its text, and the block a comment is about,
  above it (`MessageText`, `ThreadList`).

## When not

- A whole file linked from a message → its card, which **MessageText** draws.
- A description's own blocks → **ShipRichText**.

## How

```tsx
import { PartCard } from '@/components/ui/PartCard'

<PartCard address={part.address} block={part.block} nameOf={nameOf} />
```

## What it owns

- **The heading**: the title of the file it is part of, and its key under it
  ("A part of SHI-12"), read by the kit's one builder (`linkedOf`). No "Issue ·"
  before the title: the tile says what it is (Katerina, 30 Oct).
- **The read** (`usePart`), live, and the SPEC's five states (§13.6.1), as the
  kit's `PartCardState` draws them: a file a trusted deletion names says
  "deleted" (the protocol's `readAbsence`), one the reader may not see "not
  available", neither with its title; a block gone says "This part was
  deleted", and a file with no blocks "This part can't be shown", opening the
  whole file.
- **The way to it is its title**: a file of Ship's own opens in place, another
  app's in a new tab. There is no "Open" or "Open in" button: it said again
  what the title does (Katerina, 31 Oct).
