# ShipRichText

A body, drawn — every block and mark SPEC §13 defines, in both content models,
through the package's RichText. Every string reaches the DOM as a React child,
so a body written by somebody else on a shared relay is safe by construction
rather than by care.

<Canvas of={ShipRichTextStories.MarkerBody} />

## When

- Any body that came off the relay: a message, a description, another app's.
- `size="small"` — another app's message inside a card: the same text one step
  down, every structure kept.
- Whenever you have the format from the event's own tag. The caller reads it
  off the fold and passes it on.

## When not

- Never `dangerouslySetInnerHTML`, and never interpolate a title into a
  template string. On a shared relay the words were written by other people.
- Never guess the format from the body. A description that happens to begin
  with `{` is marker text, because it carries no tag.
- Do not expect a table in marker text. §13.2 has no table, so `| a | b |`
  stays the line somebody typed — that is the protocol's ruling, not Ship's.
- For the editor as well as the rendering → **LiveHeader** for a description,
  **ConversationBox** for a message.

## How

```tsx
import { ShipRichText } from '@/components/ui/ShipRichText'

<ShipRichText value={body} format={format} resolved={resolved} nameOf={nameOf} renderAfter={(block) => blockLineCards(block, resolved)} />
```

- `resolved` is keyed by URI and resolved once for the whole body, so an object
  named twice cannot be drawn in two states on one screen.
- Every pointer is its chip, alone on its line too. `renderAfter` draws what
  a description's chips ask for after their line (`blockLineCards`, SPEC
  §13.3); only a page's own description passes it, never a card's body, where
  two objects that card each other would nest forever.

## What it owns

- **What is Ship's in a body**: a person or an item a run points at
  (`Reference`), a file (`Attachment`), and a description's cards after their
  lines. Everything else — the look, tables, links, the fallback for a block it
  has never heard of — is the package's `RichText` (UIG-30, Katerina,
  28 September), the same part Peek draws with.
- **The look is the one the editor wears**: `richTextClassName()` on
  DescriptionEditor's writing surface, so neither can be restyled without the
  other.
